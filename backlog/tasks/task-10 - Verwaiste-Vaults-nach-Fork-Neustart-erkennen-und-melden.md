**Expected:** Wenn die Chain-Instanz wechselt (lokaler Fork-Neustart), erkennt das Backend, dass DB-Vaults auf der aktuellen Chain keinen Code mehr haben, und meldet das verständlich — statt pro Tick/Request kryptische Decode-Warnings zu loggen.

## Agent Brief

**Category:** enhancement
**Summary:** Stale-Vault-Erkennung: Vaults ohne On-Chain-Code erkennen, klar loggen und von teuren Reads ausnehmen.

**Current behavior:** Cockpit-/Fee-Services rufen Views auf jeder DB-Vault-Adresse auf; bei codeloser Adresse liefert eth_call 0x → BAD_DATA-Warning pro Vault und Request, unbegrenzt wiederholt.

**Desired behavior:** Das Backend prüft (z. B. beim Start und danach gecacht/periodisch) per eth_getCode, ob jede bekannte Vault-Adresse auf der aktuellen Chain Code trägt. Codelose Vaults werden EINMAL klar geloggt ("Vault <label/adresse> existiert auf dieser Chain-Instanz nicht — vermutlich Fork-Neustart; Zeile bereinigen oder Vault neu anlegen") und von Gas-Reserve-/Valuation-Reads übersprungen (Positions-/Cockpit-Antwort degradiert weiterhin pro Zeile, kein Verhaltensbruch der API). Kein automatisches Löschen von DB-Zeilen — nur erkennen, melden, überspringen.

**Key interfaces:**
- Ein kleiner Code-Existenz-Check (provider.getCode) mit Cache, konsumiert von ValuationService/FeeService (Systemgrenze: Provider — mockbar)
- Log-Vertrag: genau eine WARN pro Vault und Prozesslauf, kein Spam pro Tick/Request

**Acceptance criteria:**
- [ ] Vault mit Code: Verhalten unverändert (bestehende Tests grün)
- [ ] Vault ohne Code: keine BAD_DATA-Warning mehr; stattdessen einmalige, verständliche WARN mit Adresse/Label und Hinweis auf Fork-Neustart
- [ ] Gas-Reserve-/Valuation-Reads überspringen codelose Vaults (Antwort degradiert pro Zeile wie bisher)
- [ ] Tests: Codelos-Fall gemockt (getCode → 0x) auf beiden Konsumenten-Pfaden

**Out of scope:** Automatisches Löschen/Archivieren von DB-Zeilen; Änderungen am Indexer (der gated bereits über die Vault-Menge); Frontend-UI für Stale-Vaults.
